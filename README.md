## Overview
This repository provides:
1. A **naive** NumPy‑based gradient descent with momentum.
2. An **optimized** variant that pre‑allocates history and minimizes Python overhead.
3. A harness that runs both on a quadratic test problem and writes a markdown comparison.
4. pytest suites guaranteeing correctness and edge‑case handling.

## Tech Stack
- Python 3.10+
- NumPy for array arithmetic
- Matplotlib for optional demo visualisation
- Pytest for testing

## Theoretical Background
Gradient descent with momentum augments the basic steepest‑descent update by accumulating a velocity vector that smooths the trajectory. Formally, for parameters \theta we maintain a momentum term \(v\):
```
v_{t+1} = mu * v_t - lr * grad(f)(theta_t)
theta_{t+1} = theta_t + v_{t+1}
```
where *mu* (0 ≤ mu < 1) controls the contribution of the previous velocity. This scheme helps to overcome shallow curvature and reduces oscillations in narrow valleys, effectively approximating a low‑pass filtered version of the raw gradient.

In practice, the choice of learning rate and momentum critically influences convergence speed. Too large a learning rate can cause divergence, while excessive momentum may lead to overshoot. The benchmark explores a moderate setting (lr=0.1, mu=0.8) on a well‑conditioned quadratic, where the analytic solution is known and convergence can be measured precisely.

## Usage
Run the benchmark harness:
```bash
python harness/runner.py
```
The results are written to ``results/comparison.md``. To visualise loss curves:
```bash
python examples/run_demo.py
```
A plot ``results/demo_loss.png`` will be created.

## API Reference
### NaiveMomentumGD
```python
NaiveMomentumGD(lr: float = 0.01, momentum: float = 0.9, max_iter: int = 1000, tol: float = 1e-6)
```
- **minimize(func, grad, x0)** – Runs optimisation, returns ``(x_opt, n_iter)``.

### OptimizedMomentumGD
```python
OptimizedMomentumGD(lr: float = 0.01, momentum: float = 0.9, max_iter: int = 1000, tol: float = 1e-6)
```
- Same public interface as ``NaiveMomentumGD`` but stores loss history in a NumPy array for faster access.

## Testing
```bash
pytest -q
```
The test suite covers convergence on a simple quadratic, handling of zero‑gradient start, and verifies that the optimized history length respects ``max_iter``.

## Limitations
- Only supports dense NumPy arrays; no sparse or GPU back‑ends.
- Fixed learning‑rate schedule; does not implement adaptive methods (Adam, RMSProp).
- Benchmark problem is limited to a 2‑D quadratic; real‑world performance may differ.
